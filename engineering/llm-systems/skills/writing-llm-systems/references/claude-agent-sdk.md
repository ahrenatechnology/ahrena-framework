# Claude Agent SDK and Claude Managed Agents

For an agent that works in a workspace with Claude Code's tools (`docs/frameworks.md`). Facts read on 2026-11-15; open the linked page before relying on one.

**Install and pin.** Python `claude-agent-sdk` (import `claude_agent_sdk`), TypeScript `@anthropic-ai/claude-agent-sdk`; both bundle a native Claude Code binary ([quickstart](https://code.claude.com/docs/en/agent-sdk/quickstart)). Pin the version.

**Tools and authority.** The SDK ships built-in tools (`Read`, `Edit`, `Write`, `Glob`, `Grep`, `Bash`, `WebSearch`, `WebFetch` and more) ([agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop)). `allowed_tools` auto-approves the tools it lists but leaves the others available; `disallowed_tools` is what removes a tool; the `permission_mode` (`default`, `acceptEdits`, `plan`, `dontAsk`, `auto`, `bypassPermissions`) decides the rest ([tool permissions](https://code.claude.com/docs/en/agent-sdk/agent-loop#tool-permissions), [permission mode](https://code.claude.com/docs/en/agent-sdk/agent-loop#permission-mode)). So least authority is `disallowed_tools` for every built-in tool the task does not need, plus a mode that does not approve the rest unasked. `bypassPermissions` runs tool calls without approval, including tools not listed, and the page reserves it for isolated environments; outside one it fails `rules/tool-definitions.md` condition 5. A `PreToolUse` hook runs in your process and can reject a call ([hooks](https://code.claude.com/docs/en/agent-sdk/agent-loop#hooks)): it is where a tool's effect is gated. Your own tools come in as custom tool handlers or through MCP ([custom tools](https://code.claude.com/docs/en/agent-sdk/custom-tools), [MCP](https://code.claude.com/docs/en/agent-sdk/mcp)).

**Bound.** `ClaudeAgentOptions(max_turns=..., max_budget_usd=...)`; both default to no limit. Hitting one returns a `ResultMessage` whose subtype is `error_max_turns` or `error_max_budget_usd`; `success` is the finishing subtype ([turns and budget](https://code.claude.com/docs/en/agent-sdk/agent-loop#turns-and-budget), [handle the result](https://code.claude.com/docs/en/agent-sdk/agent-loop#handle-the-result)). Map each subtype to an outcome for the caller; a single-shot `query()` also raises after yielding an error result, so the call is wrapped to reach that mapping ([handle the result](https://code.claude.com/docs/en/agent-sdk/agent-loop#handle-the-result)).

**Stub.** No official fake is documented. Keep the code that builds the options and interprets the `ResultMessage` apart from the call that runs the SDK, and test those two parts with scripted messages; the run itself is covered by the evaluation.

**Evaluation.** A script that runs each case through the agent in a sandboxed working directory and grades the outcome, the files or state the agent left, not its last message ([Demystifying evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)). Record the cost the result reports beside the pass rate.

**Tracing.** The SDK emits nothing itself; the Claude Code process it runs exports metrics and events, and traces in beta, configured by environment variables or `options.env`, structural by default ([SDK observability](https://code.claude.com/docs/en/agent-sdk/observability#how-telemetry-flows-from-the-sdk), [traces](https://code.claude.com/docs/en/monitoring-usage#traces-beta)). Leave the content opt-ins unset unless the design places that content.

## Claude Managed Agents

A hosted harness for long-running, asynchronous work, built from an agent, an environment, a session and its events; beta behind the `managed-agents-2026-04-01` header, which the SDK sets ([overview](https://platform.claude.com/docs/en/managed-agents/overview)). The loop runs on Anthropic's side, so the tests cover the code that creates sessions and reads events, and the evaluation covers the agent. Confirm the data may leave for a hosted harness before building: the page states it is not ZDR or HIPAA eligible except self-hosted for ZDR.
