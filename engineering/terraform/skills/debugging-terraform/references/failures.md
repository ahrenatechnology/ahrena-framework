# Terraform failures: symptom, cause, confirmation, fix

Read the row whose symptom matches; confirm before fixing. Every fix is a reviewed change and a plan, never a hand edit of state.

| Symptom | Class | Usual cause | Confirm | Fix |
|---|---|---|---|---|
| `init` cannot find a provider version | version | the constraint and the lock file disagree, or the lock file was written on another platform | compare `required_providers` with `.terraform.lock.hcl` | change the constraint on purpose and run `terraform init -upgrade`; add platforms with `terraform providers lock -platform=...`; never delete the lock file |
| `init` fails on a module source | version | a git `ref` that no longer exists, a registry version withdrawn, no network to the source | read the `source` and `version` of the failing call | pin to an existing tag or version (`rules/pinning.md`) |
| `validate` reports an unsupported argument or block | configuration | the provider's major version moved and renamed or removed it | the provider's upgrade guide for the version the lock file holds | follow the upgrade guide, or hold the constraint at the previous major until the change is planned |
| `Error acquiring the state lock` | lock | another run is in progress, or a run died holding the lock | the lock info names the ID, who and when; check the pipeline for a running job | wait for the running job; if none, the lock's owner runs `terraform force-unlock <id>`; never `-lock=false` |
| an output derived from a sensitive value is refused at plan, or shows as `(sensitive value)` where a caller needs it | configuration | an output derived from a sensitive value is not marked | the output's expression references a sensitive variable or attribute | mark the output `sensitive = true`; if a caller needs the plain value, it reads it from its store, not from an output (`rules/outputs.md`) |
| plan wants to replace an object nobody changed | drift or configuration | a renamed address without a `moved` block, a provider default that changed, or an argument that forces replacement changed outside code | `-refresh-only` plan; the plan's `# forces replacement` marker names the argument | a `moved` block for a rename; set the argument explicitly for a changed default; for drift, see below |
| plan shows changes on an unchanged configuration | drift | someone changed the object outside code, or another system owns that attribute | `terraform plan -refresh-only` shows what moved | wanted: edit the code, refresh-only apply; unwanted: ordinary apply reverts it; owned elsewhere: `ignore_changes` on that attribute only (`rules/drift.md`) |
| `already exists` on create | state | the object was created outside Terraform, or by a previous apply that failed before writing state | find the object in the cloud by name | an `import` block for it, then plan |
| apply failed halfway | partial apply | a provider error on one resource after others were created | state holds what succeeded; a plan shows only what is left | fix the cause the provider's message names, plan again, apply from the new plan |
| `terraform_remote_state` returns nothing or fails | state | the producing configuration renamed or removed an output, or the reader lost access to the whole state | read the producer's outputs | publish the one value to a separate store and read it with a data source (`docs/state.md`) |
| a test applies real infrastructure and fails on credentials | configuration | the `run` block defaults to `command = apply` | the run block has no `command` | `command = plan`, or a `mock_provider` (`docs/testing.md`) |
